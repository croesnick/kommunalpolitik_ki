## Meldungen und was hilft

| Du siehst | Ursache | Das hilft |
|---|---|---|
| `setup` meldet ein fehlendes Werkzeug | Etwas aus [Schritt 1](/kommunalpolitik_ki/komki/in-betrieb-nehmen/) fehlt | Den genannten Befehl ausführen, dann `komki setup` erneut |
| `credential-missing` bei der Websuche | Beim Start wurde der Schlüssel nicht freigegeben, er fehlt, er liegt noch im Klartext vor, oder sein Siegel hat noch das alte Format (`komki secret list` zeigt „altes Siegel“, dann `komki secret set brave`); `komki up` nennt den Grund | `komki secret list` zeigt „versiegelt“, „Klartext“ oder „fehlt“. Bei „fehlt“ oder „Klartext“: `komki secret set brave`. Dann `komki down && komki up` und die Touch-ID-Abfrage bestätigen |
| `Start verweigert: nicht grün: pin …` | Ein Programm hat sich seit `komki setup` verändert (etwa nach `brew upgrade` oder einem Neubau) | Wenn du es selbst aktualisiert hast: `komki setup` und die Rückfrage mit `j` bestätigen. Sonst nicht übernehmen und herausfinden, wer das Programm verändert hat |
| `komki up` meldet nach einem Update `Γ aus dem Label-Store: Import ungültig: Bindung unveränderlich: ris-oeffentlich@1 (Inhalt weicht ab)` (je nach Store auch eine andere mitgelieferte Bindung, etwa `doc-oeffentlich@2`) | Seit Ticket #298 tragen die mitgelieferten Bindungen eine Regel für die Übergabe (`transfer`). Dein Label-Store enthält noch die ältere Fassung, und Bindungen sind unveränderlich | Den alten Store beiseitelegen und neu starten: `mv ~/.local/share/komki/registry.db ~/.local/share/komki/registry.db.vor-298`, dann `komki up`. Eigene Bindungen, die du mit `komki label import` eingespielt hattest, danach erneut importieren |
| `komki up` meldet „Γ aus dem Label-Store: …“ | Eine Bindung im Label-Store (`~/.local/share/komki/registry.db`) weicht von der Vorlage ab; Bindungen sind unveränderlich | Die abweichende Bindung unter neuer Version anlegen (etwa `@2`) statt die alte zu ändern, dann `komki up` |
| `Basis abgelehnt: Socket-Pfad zu lang: 154 Byte, macOS erlaubt höchstens 103 (…)` | Der Ordner in `KOMKI_HOME` ist zu tief verschachtelt; die Verbindungsdateien von komki dürfen unter macOS höchstens 103 Byte lang sein | Einen kürzeren Ordner wählen, etwa `KOMKI_HOME=/private/tmp/komki-test`, dann `komki setup` erneut |
| `Basis des Panes weicht ab: KOMKI_HOME=…, die Session gehört zu …` | Eine zweite Instanz nutzt denselben tmux-Server mit einer anderen Basis | `komki session` aus einer Shell starten, deren `KOMKI_HOME` zur gewünschten Instanz passt; ein von Hand gestarteter tmux-Server mit diesem Namen muss vorher beendet werden |
| `doctor` meldet ein Profil als abweichend | Instanz älter als der Code | `komki setup` schreibt die Profile neu |
| `doctor` meldet `drafter sha256` oder `Start verweigert: … drafter presence`, und `up` startet nicht | Der MTP-Drafter fehlt: Instanz von vor [#318](https://github.com/croesnick/kommunalpolitik_ki/issues/318), oder der Download ist nie gelaufen | `komki setup` lädt die 0,5-GB-Datei nach Rückfrage nach; liegt sie schon bereit (etwa `--drafter-from PFAD`), entfällt die Frage |
| `komki-mediator nicht aktiv: 'komki up' zuerst` | Vermittler läuft nicht | `komki up` |
| Ein Connector fehlt in `komki status` | Prozess abgestürzt | `komki up` startet nur das Fehlende neu |
| `komki run` legt keine Notiz an, pi meldet die Sperre | So gewollt: Jedes Schreiben braucht dein GO, und bei `komki run` fragt komki nicht | Notizen in einer Session anlegen lassen und das GO im Freigabefenster geben ([Freigabe](/kommunalpolitik_ki/komki/so-funktioniert-es/#freigabe-dein-go-für-genau-einen-aufruf)) |
| Websuche im Raum „vertraulich“ abgelehnt | So gewollt | `komki raum recherche` ([Anleitung](/kommunalpolitik_ki/komki/sicherheitsgrenze/)) |
| `rp_stand_lesen` abgelehnt, pi verlangt einen Raum mit `ratsprojekte@1` | So gewollt: Den Stand aus ratsprojekte nimmt nur der Projektraum auf | `komki raum projektraum` ([Stand lesen](/kommunalpolitik_ki/komki/so-funktioniert-es/#den-stand-aus-ratsprojekte-lesen)) |
| `rp_stand_lesen` meldet im Projektraum einen Fehler (`not-found`, `not-configured` oder keine Verbindung zum Connector) | Der Hub hat noch keinen Stand als Datei ausgegeben, oder `ratsprojekte_stand` fehlt in der `config.json` | Im Hub den Stand ausgeben; den Pfad der Datei in der `config.json` unter `ratsprojekte_stand` eintragen, dann `komki down` und `komki up` |
| pi endet nach einer Ablehnung mit einer Erklärung statt minutenlangem Weitersuchen | Die Sperre trägt einen `hinweis` für pi ([#166](https://github.com/croesnick/kommunalpolitik_ki/issues/166)); im echten Lauf endete der Angriffsfall nach 80 bis 128 s statt nach 10 Minuten | Nichts abbrechen; einzelne erlaubte Nachsuchen sind möglich und gewollt |
| `admit_document` auf ein PDF meldet einen Fehler, `doctor` bleibt aber grün | Die PDF-Lesung läuft über einen nativen Baustein (pdfium), den komki nur aus der Einzeldatei (`make komki-burrito`) laden kann. Im Escript-Betrieb (Weg `make komki` oder Homebrew-Paket) scheitert jede PDF-Lesung; `ping` im Doctor berührt den Baustein nicht ([#288](https://github.com/croesnick/kommunalpolitik_ki/issues/288) entscheidet die Programmform) | Für PDFs die Einzeldatei bauen und die Instanz damit betreiben; der Fehler im `connector-documents.log` nennt die Ursache |
| Die Aufnahme verweigert eine Datei: „Raumdokument … liegt bereits als .md/.pdf vor“ | Eine Objekt-ID darf im Raum in genau einer Form liegen: Der Dokument-Connector liest Markdown zuerst, eine zweite Form bliebe ungelesen | Die alte Fassung aus `<base>/mediator/documents/` entfernen oder die Datei unter anderem Namen (anderer Objekt-ID) aufnehmen |

Logs liegen unter `~/.local/share/komki/tmp/`: `mediator.log`, `egress.log` und je Connector eine `connector-<name>.log`. Sie enthalten keine Suchbegriffe, keine Notizinhalte und keine Schlüssel, nur Betriebsdaten: welcher Aufruf wann mit welchem Ergebnis lief und welche Adresse der Egress-Proxy verbunden hat. Was entschieden wurde, steht im Journal.

## Was noch nicht geht

- **Nur auf dem Mac.** komki braucht einen Mac mit Apple Silicon und genug Arbeitsspeicher für ein 17-GB-Modell plus 0,5-GB-Drafter (erprobt mit 64 GB), weil es die Sandbox von macOS nutzt und das Sprachmodell lokal rechnet.
- **Kein Installer.** komki wird aus dem Checkout gebaut und im Terminal eingerichtet; optional legst du dir einen lokalen Tap an (`make komki-tap`). Einen veröffentlichten Release gibt es nicht.
- **Ein Prototyp, kein geprüftes Produkt.** Die Sicherheitsprüfungen sind offen dokumentiert, ein unabhängiges Audit gibt es nicht.
- **RIS liefert nur Titel.** Ohne Zugangsdaten gibt die Ratsinformations-API keine Texte der Tagesordnungspunkte heraus ([#148](https://github.com/croesnick/kommunalpolitik_ki/issues/148)).
- **PDFs ohne Textebene.** Scans ohne Textschicht liest komki nicht, OCR gibt es nicht ([#289](https://github.com/croesnick/kommunalpolitik_ki/issues/289) klärt, ob eines gebraucht wird); die Lesung meldet einen klaren Fehler. Und PDF-Lesung braucht die Einzeldatei, nicht den Escript-Betrieb ([#288](https://github.com/croesnick/kommunalpolitik_ki/issues/288)).
- **Schreiben nur in einen Testordner.** Notizen landen nur im Ordner `komki-test/`, bestehende Notizen ändert komki nicht ([#274](https://github.com/croesnick/kommunalpolitik_ki/issues/274)).
- **Gegner auf dem eigenen Rechner sind nicht abgedeckt.** komki schützt vor einem manipulierten Agenten, nicht vor Schadsoftware, die schon unter deinem Benutzer läuft.
