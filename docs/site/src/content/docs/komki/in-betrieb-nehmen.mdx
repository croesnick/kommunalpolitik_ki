Etwa 15 Minuten auf einem Mac mit Apple Silicon. Alle Befehle laufen in einem Terminal im Repo. Die Ausgaben stammen aus echten Testläufen; Prozessnummern und Zeiten sehen bei dir anders aus.

<Aside>
Du brauchst node, das pi-Paket (`npm install -g @earendil-works/pi-coding-agent`), `llama-server` (`brew install llama.cpp`), Elixir und das gemma-Modell. Was komki im Einzelnen erwartet, steht im [README von komki_cli](https://github.com/croesnick/kommunalpolitik_ki/blob/main/apps/komki_cli/README.md).
</Aside>

<Steps>

1. ### Stand holen und Kurzbefehle setzen

   `B` ist deine komki-Instanz. Der Alias erspart dir den langen Pfad zu `komki`.

   ```sh
   cd ~/projects/kommunalpolitik_ki
   git switch main && git pull
   B=~/.local/share/komki
   alias komki="$PWD/apps/komki_cli/komki"
   ```

2. ### Programme bauen und ablegen

   Sechs kleine Programme: komki selbst, der Vermittler, der Egress-Proxy und die drei Connectoren. komki findet sie in `$B/bin`.

   ```sh
   for app in komki_cli komki_mediator komki_egress komki_connector_ris komki_connector_web komki_connector_vault; do
     (cd apps/$app && mix deps.get >/dev/null && mix escript.build)
   done
   mkdir -p $B/bin
   cp apps/komki_mediator/komki-mediator apps/komki_egress/komki-egress \
      apps/komki_connector_ris/komki-connector-ris apps/komki_connector_web/komki-connector-web \
      apps/komki_connector_vault/komki-connector-vault $B/bin/
   ```

   ```text frame="terminal" title="Das siehst du"
   Generated escript komki with MIX_ENV=dev
   Generated escript komki-mediator with MIX_ENV=dev
   Generated escript komki-egress with MIX_ENV=dev
   Generated escript komki-connector-ris with MIX_ENV=dev
   Generated escript komki-connector-web with MIX_ENV=dev
   Generated escript komki-connector-vault with MIX_ENV=dev
   ```

3. ### Test-Vault einlegen

   Zum Ausprobieren ein erfundener Vault aus der Stadtratsarbeit (Buchloe, fiktiv): öffentliche und vertrauliche Notizen, eine Notiz mit einem eingeschleusten Angriffstext und eine vertrauliche Notiz mit dem Marker `GEHEIM-MARKER-7Q4Z`. Dein echter Obsidian-Vault bleibt unberührt.

   ```sh
   mkdir -p $B/vault
   cp -R apps/komki_connector_vault/priv/test-vault/. $B/vault/
   ```

   Der Vault-Connector zeigt nur Notizen mit einem Label im Frontmatter, etwa `komki_labels: [vault-oeffentlich@1]`. Alles ohne Label ist für komki unsichtbar.

4. ### Instanz anlegen oder auffrischen

   Schreibt Konfiguration und alle Sandbox-Profile. Dabei wird das Modell kopiert und per Prüfsumme kontrolliert. Das dauert etwa 30 Sekunden.

   ```sh
   komki init --force --vault-dir $B/vault
   ```

   ```text frame="terminal" title="Das siehst du"
   init ok
   base-dir:   ~/.local/share/komki
   port:       49524
   mediator-sock: ~/.local/share/komki/run/mediator.sock
   ctx:        131072
   gguf:         ~/.local/share/komki/models/gemma-4-26B-A4B-it-UD-Q4_K_XL.gguf
   gguf-sha256:  ef728c8e0c33…6e30c (pinned, verified)
   ```

   Auf einem neuen Rechner ohne Instanz ergänzt du `--gguf-from PFAD/ZUM/MODELL.gguf` und lässt `--force` weg.

5. ### Alte Raumvorlage beiseitelegen

   Nur für Instanzen von vor den Connectoren, also auch deine. Ihre Registry und ihr Raum kennen RIS, Web und Vault noch nicht, und der Vermittler würde jede Anfrage ablehnen. Beim nächsten Start legt er die neuen Vorlagen an (Raum „recherche“). Dein Journal bleibt erhalten.

   ```sh
   mv $B/mediator/registry.json $B/mediator/registry.json.vor-connectoren
   mv $B/mediator/room.json $B/mediator/room.json.vor-connectoren
   ```

6. ### Brave-Key prüfen

   Der Befehl prüft nur, dass der Eintrag im Schlüsselbund da ist. Der Key selbst wird nicht angezeigt.

   ```sh
   security find-generic-password -s brave-search-api >/dev/null && echo "Key vorhanden"
   ```

   ```text frame="terminal" title="Das siehst du"
   Key vorhanden
   ```

   Fehlt er, legst du ihn so an: `security add-generic-password -s brave-search-api -a "$USER" -w`. Beim ersten Start fragt macOS, ob `security` zugreifen darf; dann „Immer erlauben“ wählen.

7. ### Alles starten

   `komki up` startet die Prozesse in fester Reihenfolge, jeden in seiner eigenen Sandbox. Läuft llama schon, wird es nur geprüft.

   ```sh
   komki up
   ```

   ```text frame="terminal" title="Das siehst du"
   llama up: pid 26409 (health 200)
   egress up: pid 37952
   connector-ris up: pid 37979
   connector-vault up: pid 38014
   connector-web up: pid 38042
   mediator up: pid 38069 (tools: ping, admit_document, ris_search, ris_show,
                           vault_read, vault_search, vault_write_test, web_search)
   ```

8. ### Gesundheitscheck

   `komki doctor` prüft gut 30 Dinge: Werkzeuge, Prüfsummen, ob jedes Sandbox-Profil exakt so ist wie erwartet, ob der Key da ist und ob jeder Connector antwortet. Wichtig ist die letzte Zeile.

   ```sh
   komki doctor
   ```

   ```text frame="terminal" title="Das siehst du (Ende)"
   …
   ok: mediator profile (regeneration byte-stabil)
   ok: egress profile (regeneration byte-stabil)
   ok: credential BRAVE_API_KEY (Schluesselbund-Eintrag 'brave-search-api' vorhanden)
   ok: ping ris (komki-ris/1)
   ok: ping vault (komki-vault/1)
   ok: ping web (komki-web/1)
   doctor: ok
   ```

9. ### Erster Auftrag

   Ein einmaliger Lauf: pi recherchiert in allen drei Quellen und legt eine Notiz mit Quellen an. Dauert etwa eine Minute.

   ```sh
   komki run "Ich bereite mich auf das Thema Radverkehr in Buchloe vor. 1) Suche im RIS mit ris_search nach 'Radweg'. 2) Suche im Web mit web_search nach 'Förderung Radwege Bayern Kommunen 2026'. 3) Suche im Vault mit vault_search nach 'Radverkehr' und lies die passendste Notiz. 4) Lege mit vault_write_test eine Notiz 'Vorbereitung Radverkehr' an: höchstens fünf Stichpunkte, jeder mit Quelle. Antworte mit der note_id und zwei Sätzen Zusammenfassung."
   ```

   ```text frame="terminal" title="Das siehst du"
   note_id: komki-test/2026-10-24-vorbereitung-radverkehr.md

   Die vorbereitete Notiz fasst die lokalen Ziele für einen durchgehenden Radweg
   in Buchloe sowie die verfügbaren bayerischen Fördermöglichkeiten zusammen. Sie
   beleuchtet sowohl die baulichen Engpässe in der Bahnhofstraße als auch die
   hohen Fördersätze von bis zu 90 % für Kommunen.
   ```

   Die neue Notiz liegt in deinem Test-Vault:

   ```sh
   cat $B/vault/komki-test/*vorbereitung-radverkehr.md
   ```

   ```text frame="terminal" title="Das siehst du"
   ---
   komki_labels: [ris-oeffentlich@1, vault-oeffentlich@1, web-oeffentlich@1]
   title: "Vorbereitung Radverkehr"
   ---
   - Ziel: Durchgehender Radweg Bahnhof-Schulzentrum (note_id: Projekte/Verkehr/Radverkehrskonzept.md)
   - Engpass: Bahnhofstraße mit Parkstreifen (note_id: Projekte/Verkehr/Radverkehrskonzept.md)
   - Förderung: Bis zu 80% durch BayFAG/Radoffensive (URL: https://www.radverkehr.bayern.de/foerderung/index.php)
   …
   ```

   Die Notiz trägt die Labels aller Quellen, aus denen sie entstanden ist. Liest sie später jemand, weiß das System, woher ihr Inhalt stammt.

10. ### Interaktiv arbeiten

    Für längere Arbeit gibt es die Session in tmux. Du schreibst wie in einem Chat; pi nutzt die Tools selbst.

    ```sh
    komki session
    ```

    Gute erste Fragen:

    - „Welche Notizen zum Haushalt gibt es im Vault? Fasse sie zusammen.“
    - „Suche im RIS nach Bahnhofstraße und zeige mir den ersten Treffer im Detail.“
    - „Was sagt das Web zu Förderprogrammen für Bürgerhäuser in Bayern?“

    Abkoppeln, ohne zu beenden: `Ctrl+B`, dann `d`. Wieder dazu: `komki session --continue`.

11. ### Nachvollziehen und stoppen

    Jede Entscheidung steht im Journal. Dieser Befehl prüft, dass die Kette lückenlos und unverändert ist:

    ```sh
    $B/bin/komki-mediator verify-journal --base $B
    ```

    ```text frame="terminal" title="Das siehst du"
    {"chained":28,"head_hash":"sha256:79b15e37…","records":28,"result":"valid"}
    ```

    Wenn du fertig bist, stoppt `komki down` alles, auch llama:

    ```sh
    komki down
    ```
