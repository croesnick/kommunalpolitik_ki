Etwa zehn Minuten auf einem Mac mit Apple Silicon, wenn das Modell schon auf der Platte liegt. Die Ausgaben stammen aus echten Testläufen; Prozessnummern und Zeiten sehen bei dir anders aus.

<Aside>
Du brauchst llama.cpp, node, das pi-Paket, Elixir und tmux. Fehlt etwas, nennt `komki setup` den passenden Installationsbefehl, du musst also nicht vorher nachsehen. Dazu kommt das gemma-Modell (17 GB). Bald lädt `komki setup` es selbst herunter, und eine Installation über Homebrew ersetzt den Bauschritt.
</Aside>

<Steps>

1. ### komki bauen

   Im Repo baut ein Befehl komki und seine Bausteine (Vermittler, Egress-Proxy, drei Connectoren) und legt sie ab. `komki` liegt danach in `~/.local/bin` und ist von überall aufrufbar.

   ```sh
   cd ~/projects/kommunalpolitik_ki
   git switch main && git pull
   make komki
   ```

   ```text frame="terminal" title="Das siehst du (Ende)"
   Generated escript komki-connector-vault with MIX_ENV=dev

   komki gebaut: ~/.local/bin/komki, Bausteine unter ~/.local/share/komki/bin
   Weiter mit: komki setup
   ```

2. ### Einrichten

   `komki setup` prüft die Werkzeuge, fragt nach dem Vault, legt die Instanz an, fragt den Brave-Key ab, falls er fehlt, startet alles und prüft es. Zum Ausprobieren nimmst du den Test-Vault: erfundene Notizen aus der Stadtratsarbeit (Buchloe, fiktiv), öffentliche und vertrauliche, dazu eine Notiz mit eingeschleustem Angriffstext. Dein echter Obsidian-Vault bleibt unberührt.

   ```sh
   komki setup --demo --gguf-from PFAD/ZUM/gemma-4-26B-A4B-it-UD-Q4_K_XL.gguf
   ```

   ```text frame="terminal" title="Das siehst du"
   Werkzeuge   ok (llama-server, node, pi, Erlang (escript), komki-mediator, komki-egress, komki-connector-ris, komki-connector-vault, komki-connector-web)
   Vault       Test-Vault mit 11 erfundenen Notizen unter ~/.local/share/komki/vault
   Instanz     wird angelegt unter ~/.local/share/komki (prueft und kopiert das Modell, etwa 30 s)
   Instanz     angelegt
   brave       ok (Schluesselbund-Eintrag 'brave-search-api')
   Start       llama, Egress, Connectoren und Vermittler (beim ersten Mal bis zu einer Minute)
   llama up: pid 40047 (health 200)
   egress up: pid 40098
   connector-ris up: pid 40125
   connector-vault up: pid 40152
   connector-web up: pid 40189
   mediator up: pid 40217 (tools: ping, admit_document, ris_search, ris_show, vault_read, vault_search, vault_write_test, web_search)
   Pruefung    doctor ok

   Fertig. Probier zum Beispiel:
     komki run "Was steht im RIS zum Radverkehrskonzept?"
     komki session
   ```

   Fehlt der Brave-Key, fragt `setup` ihn verdeckt ab: Die Eingabe erscheint nicht auf dem Bildschirm und landet direkt im macOS-Schlüsselbund. Später geht das auch einzeln mit `komki secret set brave`. Für deinen eigenen Vault nimmst du `--vault-dir PFAD` statt `--demo`. komki sieht dort nur Notizen mit einem Label im Frontmatter, etwa `komki_labels: [vault-oeffentlich@1]`.

3. ### Erster Auftrag

   Ein einmaliger Lauf: pi recherchiert in allen drei Quellen und legt eine Notiz mit Quellen an. Läuft komki gerade nicht, startet `run` es vorher selbst.

   ```sh
   komki run "Ich bereite mich auf das Thema Radverkehr in Buchloe vor. 1) Suche im RIS mit ris_search nach 'Radweg'. 2) Suche im Web mit web_search nach 'Förderung Radwege Bayern Kommunen 2026'. 3) Suche im Vault mit vault_search nach 'Radverkehr' und lies die passendste Notiz. 4) Lege mit vault_write_test eine Notiz 'Vorbereitung Radverkehr' an: höchstens fünf Stichpunkte, jeder mit Quelle. Antworte mit der note_id und zwei Sätzen Zusammenfassung."
   ```

   ```text frame="terminal" title="Das siehst du"
   note_id: komki-test/2026-10-24-vorbereitung-radverkehr.md

   Die vorbereitete Notiz fasst die lokalen Ziele für einen durchgehenden Radweg
   in Buchloe sowie die verfügbaren bayerischen Fördermöglichkeiten zusammen. Sie
   beleuchtet sowohl die baulichen Engpässe in der Bahnhofstraße als auch die
   hohen Fördersätze von bis zu 90 % für Kommunen.
   ```

   Die neue Notiz liegt im Test-Vault unter `komki-test/` und trägt die Labels aller Quellen, aus denen sie entstanden ist. Liest sie später jemand, weiß das System, woher ihr Inhalt stammt.

4. ### Interaktiv arbeiten

   Für längere Arbeit gibt es die Session in tmux. Du schreibst wie in einem Chat; pi nutzt die Tools selbst.

   ```sh
   komki session
   ```

   Gute erste Fragen:

   - „Welche Notizen zum Haushalt gibt es im Vault? Fasse sie zusammen.“
   - „Suche im RIS nach Bahnhofstraße und zeige mir den ersten Treffer im Detail.“
   - „Was sagt das Web zu Förderprogrammen für Bürgerhäuser in Bayern?“

   Abkoppeln, ohne zu beenden: `Ctrl+B`, dann `d`. Wieder dazu: `komki session --continue`.

5. ### Nachvollziehen und stoppen

   Jede Entscheidung steht im Journal. Dieser Befehl prüft, dass die Kette lückenlos und unverändert ist:

   ```sh
   komki journal verify
   ```

   ```text frame="terminal" title="Das siehst du"
   Journal ok: 2 Eintraege, lueckenlos verkettet und unveraendert
   Kopf: sha256:b693e6d3bab75349d9e71a291512651d18ca67c07b60e7ccd14ef3503d9abbad
   ```

   Wenn du fertig bist, stoppt `komki down` alles, auch llama:

   ```sh
   komki down
   ```

</Steps>

<Aside type="caution" title="Instanz von vor den Connectoren">
Hast du komki schon vor RIS, Web und Vault benutzt, kennen `registry.json` und `room.json` deiner Instanz die neuen Quellen noch nicht, und der Vermittler lehnt jede Anfrage ab. Lege beide einmalig beiseite; beim nächsten Start entstehen die neuen Vorlagen, dein Journal bleibt erhalten. Bald erledigt komki das selbst.

```sh
cd ~/.local/share/komki/mediator
mv registry.json registry.json.vor-connectoren
mv room.json room.json.vor-connectoren
```
</Aside>
